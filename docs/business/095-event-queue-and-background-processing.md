# صف رویداد و پردازش پس‌زمینه در CRM فانل

- وضعیت: تصمیم معماری تأییدشده برای ادامه‌ی طراحی
- شماره‌ی تصمیم: ۰۹۵
- تاریخ ثبت: ۲۰۲۶-۱۰-۱۶
- دامنه: دریافت و پردازش رویدادهای اتصال و اجرای کارهای سنگین خارج از مسیر پاسخ API

## تصمیم

رویدادهای اتصال باید از مسیر صف پایدار و پردازش سریع عبور کنند تا داده هنگام اختلال از بین نرود. صف برای تأخیر عمدی استفاده نمی‌شود. محاسبات سنگین تحلیل و هوش مصنوعی از پاسخ API جدا اجرا می‌شوند.

## اصول

- رویداد پذیرفته‌شده تا پردازش موفق یا رسیدگی روشن به خطا حفظ شود.
- کارهای سنگین بر پاسخ فوری API اثر نگذارند.
- وضعیت انتظار، پردازش، تأخیر و خطا قابل‌مشاهده باشد.
- پردازش مجدد کار ناموفق به نتیجه یا اقدام تکراری منجر نشود.
- پردازش رویدادها با فضای کاری، مجوز و منبع داده‌ی مربوط کنترل شود.

## معیار پذیرش

- اختلال موقت باعث حذف رویداد پذیرفته‌شده نشود.
- کارهای تحلیل و AI بار پاسخ درخواست‌های عادی را مختل نکنند.
- کاربر بتواند وضعیت کار معوق یا خطادار را ببیند.
- بازیابی و پردازش مجدد نتیجه‌ی قابل‌ردیابی و بدون تکرار داشته باشد.
