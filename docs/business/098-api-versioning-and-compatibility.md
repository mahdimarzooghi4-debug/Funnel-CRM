# نسخه‌بندی و سازگاری API محصولات فانل

- وضعیت: تصمیم معماری تأییدشده برای ادامه‌ی طراحی
- شماره‌ی تصمیم: ۰۹۸
- تاریخ ثبت: ۲۰۲۶-۱۰-۱۶
- دامنه: قرارداد API میان CRM، محصولات فانل و سامانه‌های مشتری

## تصمیم

قراردادهای API میان CRM، محصولات فانل و سامانه‌های مشتری نسخه‌دار باشند. تغییرات سازگار تا حد ممکن بدون ارتقای هم‌زمان مصرف‌کنندگان منتشر شوند. تغییر ناسازگار نسخه‌ی جدید بگیرد و برای نسخه‌ی قبلی مسیر مهاجرت و پایان پشتیبانی مشخص شود. انتخاب سبک API و ابزار اجرایی به طراحی فنی موکول می‌شود.

## اصول

- هر API قرارداد روشن و نسخه‌ی قابل‌شناسایی داشته باشد.
- تغییرات سازگار، مصرف‌کننده‌های موجود را از کار نیندازند.
- برای تغییر ناسازگار، نسخه‌ی جدید و مسیر مهاجرت مستند شود.
- اعلام پایان پشتیبانی نسخه‌ی قبلی با مهلت و برنامه‌ی مشخص انجام شود.
- نسخه‌ی API از نسخه‌ی محصول و از نسخه‌ی رویدادهای Kafka مستقل باشد.
- نوع API، قالب قرارداد و ابزار اعتبارسنجی در این تصمیم تعیین نمی‌شود.

## معیار پذیرش

- مصرف‌کننده بتواند نسخه‌ی قرارداد API مورد استفاده‌اش را مشخص کند.
- انتشار تغییر سازگار، مصرف‌کننده‌ی منطبق با قرارداد قبلی را مختل نکند.
- تغییر ناسازگار تا زمان مهاجرت برنامه‌ریزی‌شده، نسخه‌ی قبلی را بی‌خبر از دسترس خارج نکند.
- وضعیت پشتیبانی و مهلت مهاجرت نسخه‌های قدیمی قابل‌مشاهده باشد.
- ناسازگاری قرارداد پیش از انتشار قابل‌شناسایی و آزمون باشد.
