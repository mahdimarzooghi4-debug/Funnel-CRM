# ارزیابی مجوزهای اقدام CRM

- بک‌لاگ: زیرساخت دسترسی برای CRM-DOM-01 و CRM-DOM-02
- migration: `20261018_02`
- وضعیت: evaluator پایگاه‌داده‌ای و کاتالوگ مجوز آماده؛ اتصال endpointها در برش بعد

## مجوزهای CRM

| کلید | کاربرد |
|---|---|
| `crm.settings:manage` | مدیریت تنظیمات فضای کاری |
| `crm.pipeline:manage` | مدیریت قیف و مرحله‌ها |
| `crm.custom_field:manage` | مدیریت تعریف فیلدهای سفارشی |
| `crm.profile:view` | مشاهده‌ی پرونده |
| `crm.profile:create` | ساخت پرونده |
| `crm.profile:update` | ویرایش پرونده |
| `crm.profile:archive` | بایگانی پرونده |
| `crm.profile:export` | خروجی‌گرفتن از داده‌ی پرونده |

مجوز حذف مستقل تعریف نشده است. اقدام ناشناخته یا فاقد کاتالوگ رد می‌شود. مجوز خروجی مستقل از مشاهده باقی می‌ماند.

## ارزیابی دامنه

`has_crm_permission` عضویت جاری را دوباره از پایگاه‌داده می‌خواند، واحد هدف را در همان tenant پیدا می‌کند و مسیر والدهای آن را با CTE بازگشتی می‌سازد. یک تخصیص نقش باید هم مجوز اقدام و هم دامنه‌ی لازم را داشته باشد؛ ترکیب دسترسی یک نقش با دامنه‌ی نقش دیگر مجاز نیست. تخصیص به واحد والد، در واحدهای زیرمجموعه ارث می‌رسد.

## آزمون‌ها

آزمون PostgreSQL با نقش runtime و RLS موارد زیر را پوشش می‌دهد: ارث‌بری دامنه به تیم، منع دسترسی به شعبه‌ی دیگر، جدانبودن مجوز و دامنه میان دو نقش، رد اقدام ناشناخته، وجود کاتالوگ و رد عضویت تعلیق‌شده.

## مرز اجرا

این برش قابلیت ارزیابی و کلیدهای مجوز را اضافه می‌کند. endpoint مدیریتی یا CRUD هنوز در معرض API نیست؛ مرحله‌ی بعد باید evaluator را به dependencyهای مسیرهای CRM وصل کند و برای فهرست‌ها نیز فیلتر دامنه‌ای اعمال کند تا کنترل مجوز با کنترل خود ردیف داده همراه باشد.
