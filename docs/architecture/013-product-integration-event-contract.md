# قرارداد اتصال محصولات و رویدادهای CRM

- وضعیت: قرارداد پایه‌ی CRM-FND-07
- دامنه: اتصال محصولات هر کسب‌وکار، از جمله محصولات فانل، به Workspace همان کسب‌وکار
- مسیر HTTP: `POST /api/v1/integrations/events`

## پاکت رویداد نسخه‌ی ۱

| فیلد | نوع | کاربرد |
|---|---|---|
| `event_id` | UUID | کلید idempotency تولیدکننده |
| `tenant_id` | UUID | Workspace مقصد؛ صرفاً ادعای قابل‌بررسی است و مجوز ایجاد نمی‌کند |
| `source_product` | شناسه‌ی متنی پایدار | محصول مبدأ |
| `event_type` | شناسه‌ی متنی پایدار | نوع رویداد |
| `contract_name` | شناسه‌ی قرارداد | نام قرارداد payload |
| `contract_version` | عدد صحیح مثبت | نسخه‌ی قرارداد |
| `correlation_id` | UUID | هم‌بستگی چند رویداد در یک عملیات |
| `occurred_at` | زمان ISO 8601 با timezone | زمان رخداد در مبدأ |
| `payload` | شیء JSON تا ۶۴ KiB | داده‌ی دامنه‌ی همان رویداد |

فیلد ناشناخته رد می‌شود. timestamp بدون timezone و payload بزرگ‌تر از سقف رد می‌شوند. فیلدهای پاکت در OpenAPI و مدل Pydantic ثبت شده‌اند.

## هویت و محدوده‌ی مجوز

لایه‌ی احراز هویت باید اعتبار محصول را بررسی کند و شیء `VerifiedProductConnection` را در `request.state.verified_product_connection` قرار دهد. هدر یا شناسه‌ی فرستاده‌شده در بدنه به‌تنهایی هویت محسوب نمی‌شود. اتصال تأییدشده به یک `tenant_id`، یک `source_product`، فهرست صریح `event_type`های مجاز و نسخه‌های مجاز قرارداد متصل است. هر اختلاف یا نبود مجوز با ۴۰۳ رد می‌شود؛ نبود هویت تأییدشده با ۴۰۱ رد می‌شود.

## دریافت و idempotency

endpoint پس از تأیید دامنه، رویداد را به `ProductEventSink` می‌سپارد. در پیکربندی معمول، اگر `app.state.session_factory` موجود باشد، sink PostgreSQL رویداد را در جدول `integration_event_inbox` در همان Workspace ثبت و commit می‌کند؛ فقط پس از commit پاسخ ۲۰۲ برمی‌گردد. کلید یکتا برابر `(tenant_id, source_product, event_id)` است. ارسال دوباره‌ی همان پاکت رسید تکراری می‌دهد؛ استفاده‌ی مجدد از شناسه با پاکت متفاوت با ۴۰۹ رد می‌شود. نبود sink و session factory با ۵۰۳ پاسخ می‌دهد.

جدول inbox دارای RLS اجباری tenant است. اتصال تأییدشده باید از middleware مورد اعتماد ساخته شود؛ این migration به‌تنهایی credential محصول را احراز نمی‌کند. رسید پذیرفته‌شده یعنی رویداد پایدار ذخیره شده و در انتظار پردازش است، نه اینکه منطق تجاری آن اجرا شده باشد. audit فقط نوع/نسخه‌ی قرارداد و شناسه‌ی اتصال را ثبت می‌کند و payload را کپی نمی‌کند.

هیچ محصول فانل دسترسی ویژه یا مجوز بین Workspaceها دریافت نمی‌کند.
