# قرارداد اتصال محصولات و رویدادهای CRM

- وضعیت: قرارداد پایه‌ی CRM-FND-07
- دامنه: اتصال محصولات هر کسب‌وکار، از جمله محصولات فانل، به Workspace همان کسب‌وکار
- مسیر HTTP: `POST /api/v1/integrations/events`

## پاکت رویداد نسخه‌ی ۱

| فیلد | نوع | کاربرد |
|---|---|---|
| `event_id` | UUID | کلید idempotency تولیدکننده |
| `tenant_id` | UUID | Workspace مقصد؛ صرفاً ادعای قابل‌بررسی است و مجوز ایجاد نمی‌کند |
| `source_product` | شناسه‌ی متنی پایدار | محصول مبدأ |
| `event_type` | شناسه‌ی متنی پایدار | نوع رویداد |
| `contract_name` | شناسه‌ی قرارداد | نام قرارداد payload |
| `contract_version` | عدد صحیح مثبت | نسخه‌ی قرارداد |
| `correlation_id` | UUID | هم‌بستگی چند رویداد در یک عملیات |
| `occurred_at` | زمان ISO 8601 با timezone | زمان رخداد در مبدأ |
| `payload` | شیء JSON تا ۶۴ KiB | داده‌ی دامنه‌ی همان رویداد |

فیلد ناشناخته رد می‌شود. timestamp بدون timezone و payload بزرگ‌تر از سقف رد می‌شوند. فیلدهای پاکت در OpenAPI و مدل Pydantic ثبت شده‌اند.

## هویت و محدوده‌ی مجوز

لایه‌ی احراز هویت باید اعتبار محصول را بررسی کند و شیء `VerifiedProductConnection` را در `request.state.verified_product_connection` قرار دهد. هدر یا شناسه‌ی فرستاده‌شده در بدنه به‌تنهایی هویت محسوب نمی‌شود. اتصال تأییدشده به یک `tenant_id`، یک `source_product`، فهرست صریح `event_type`‌های مجاز و نسخه‌های مجاز قرارداد متصل است. هر اختلاف یا نبود مجوز با ۴۰۳ رد می‌شود؛ نبود هویت تأییدشده با ۴۰۱ رد می‌شود.

## دریافت و idempotency

endpoint فقط پس از تأیید دامنه، رویداد را به `ProductEventSink` می‌سپارد. پیاده‌سازی sink باید رویداد را به‌صورت پایدار و idempotent ثبت کند و تنها پس از commit رسید برگرداند. کلید یکتای پیشنهادی inbox برابر `(tenant_id, source_product, event_id)` است. تا پیش از پیکربندی sink پایدار، endpoint با ۵۰۳ پاسخ می‌دهد و رویداد را موفق اعلام نمی‌کند.

این بسته قرارداد و enforcement سطح API را فراهم می‌کند؛ اعتبارسنجی credential محصول و ذخیره‌سازی inbox باید در بسته‌ی زیرساخت مربوط به اتصال/رویداد تکمیل شوند. هیچ محصول فانل دسترسی ویژه یا مجوز بین Workspaceها دریافت نمی‌کند.
