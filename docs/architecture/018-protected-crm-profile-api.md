# API پرونده‌های CRM با کنترل دامنه

- بک‌لاگ: عملیات پرونده‌ی شخص و سازمان
- مسیرها: `/api/v1/crm/profiles`
- وضعیت: فهرست، ساخت، مشاهده و ویرایش با مجوز اقدام و دامنه‌ی سازمانی

## عملیات

| عملیات | مجوز |
|---|---|
| فهرست و مشاهده | `crm.profile:view` |
| ساخت | `crm.profile:create` |
| ویرایش نام و مرحله‌ی چرخه‌ی عمر | `crm.profile:update` |

شناسه‌ی Workspace فقط از انتخاب هدر گرفته و سپس با عضویت فعال اعتبارسنجی می‌شود. شناسه‌ی واحد سازمانی ورودی تا عبور از ارزیاب مجوز قابل‌اعتماد نیست.

## محدودیت ردیف‌ها

فهرست با CTE دامنه را مستقیماً در پرس‌وجوی پایگاه‌داده اعمال می‌کند؛ ردیف شعبه‌ی غیرمجاز نه در فهرست و نه در شمارش کل ظاهر می‌شود. درخواست مستقیم برای پروفایل خارج از دامنه پاسخ ۴۰۴ می‌گیرد تا وجود پرونده افشا نشود. ساخت و ویرایش پیش از نوشتن، مجوز همان عملیات را روی واحد پرونده بررسی می‌کنند.

ساخت پروفایل ابتدا anchor tenant را درج و سپس خود پروفایل را ایجاد می‌کند. تغییرات پروفایل از ممیزی موجود عبور می‌کنند؛ نام مشتری در snapshot ممیزی ثبت نمی‌شود.

## آزمون

آزمون API با نقش PostgreSQL محدودشده، مسیر واقعی ASGI، middleware هویت آزمایشی و دیتابیس اجرا می‌شود. ساخت مجاز و غیرمجاز، فهرست محدودشده، خواندن مستقیم بیرون دامنه، ویرایش مجاز، رد مقدار null و رفتار عضویت بدون مجوز را می‌آزماید.

## مرز این برش

این API اطلاعات تماس، مقادیر فیلدهای سفارشی، ادغام تکراری، حذف، بایگانی و خروجی‌گرفتن را پیاده نمی‌کند. برای هرکدام باید ابتدا قرارداد داده و مجوز متناظر به مسیرهای scoped اضافه شود.
