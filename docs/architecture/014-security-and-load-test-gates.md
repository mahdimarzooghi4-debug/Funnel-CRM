# آزمون امنیت و بار برای پایه‌ی CRM

- پیوند بک‌لاگ: CRM-FND-08
- دامنه‌ی این بسته: جداسازی tenant و مسیر دریافت رویداد محصول
- اجرا: `python -m pytest`

## دروازه‌های امنیتی

- آزمون‌های PostgreSQL موجود جداسازی RLS، pool reuse، محدودیت‌های کلید خارجی بین tenantها، مجوز نقش runtime و مسیر ممیزی را بررسی می‌کنند.
- `tests/test_integration_security_load.py` بررسی می‌کند که API بدون هویت تأییدشده با ۴۰۱ بسته بماند.
- همان فایل درخواست‌های tenant، محصول مبدأ، نوع رویداد و نسخه‌ی قرارداد خارج از grant را با ۴۰۳ رد می‌کند.
- مسیر رویداد بدون inbox پایدار باید ۵۰۳ بدهد، نه پاسخ موفق.

## آزمون هم‌زمانی پایه

آزمون `test_product_event_api_concurrency_smoke` تعداد ۲۵۶ درخواست API را با حداکثر هم‌زمانی ۳۲ از راه ASGI اجرا و تعداد پاسخ موفق، ثبت inbox و زمان کل را گزارش می‌کند. این آزمون برای کشف regressionهای واضح در مرز API است؛ برآورد ظرفیت production نیست و sink آن فقط fixture آزمون است.

سنجه‌ی ظرفیت واقعی PostgreSQL و workerها به زیرساخت stage و هدف ظرفیت مصوب نیاز دارد. از نتیجه‌ی این smoke test نباید ظرفیت کاربران یا درخواست‌های production استنتاج کرد.
