# پرونده‌های مشتری با فیلدهای سفارشی

- اپیک: `CRM-DOM-01` و `CRM-DOM-02`
- migration: `20261018_06`
- وضعیت: ذخیره و بازیابی مقادیر فیلدهای تعریف‌شده برای پروفایل شخص/سازمان

## داده و اعتبارسنجی

مقدار هر فیلد در ردیف جداگانه و با FK همان tenant به پرونده و تعریف فیلد ذخیره می‌شود. Trigger پایگاه‌داده کنترل می‌کند که نوع پروفایل با نوع موجودیت تعریف و فیلد فعال سازگار باشد. مقدار JSON محدود به scalarهای متن، عدد یا boolean است؛ سقف ذخیره‌سازی هر مقدار 32 KiB است.

API مقدار را بر اساس تعریف معتبر می‌کند: متن غیرخالی، عدد متناهی، boolean واقعی، تاریخ ISO `YYYY-MM-DD` یا یکی از گزینه‌های انتخابی. آرایه، شیء، null، مقدار نامعتبر و فیلد متعلق به نوع پروفایل دیگر رد می‌شوند. لیست نمایشی حداکثر ۲۰۰ تعریف فعال را برمی‌گرداند و برای فیلدهایی که مقدار ندارند `null` نشان می‌دهد.

`is_required` و گزینه‌ها به فرم مصرف‌کننده برگردانده می‌شوند. این API برای ویرایش جزئی طراحی شده و به‌تنهایی الزام فیلدها در ساخت پرونده را enforce نمی‌کند؛ اتصال اعتبارسنجی required به ساخت پرونده در مرحله‌ی فرم/گردش‌کار انجام می‌شود.

## API و دسترسی

- `GET /api/v1/crm/profiles/{profile_id}/custom-fields`: تعاریف فعال و مقادیر فعلی
- `PUT /api/v1/crm/profiles/{profile_id}/custom-fields/{field_key}`: ثبت یا جایگزینی یک مقدار

هر مسیر علاوه بر مشاهده‌ی پرونده و دامنه‌ی سازمانی، به مجوز مستقل مشاهده یا به‌روزرسانی مقادیر نیاز دارد. RLS اجباری و محدودیت‌های FK همان-tenant در پایگاه‌داده اجرا می‌شوند. تغییرات همان تراکنش عامل‌محور ممیزی می‌شوند؛ snapshot فقط کلید فیلد، نوع و وجود مقدار را ثبت می‌کند و مقدار واقعی را افشا نمی‌کند.

## آزمون

آزمون PostgreSQL/API انواع text, number, boolean, date و choice، حالت خالی، تغییر مقدار، رد نوع یا گزینه‌ی نادرست، جداسازی نوع پروفایل، کنترل مجوز و حذف مقدار از ممیزی را پوشش می‌دهد.
