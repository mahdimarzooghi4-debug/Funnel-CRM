# Sprint 110: Outcomes on generated follow-up tasks

A follow-up task created from a callback or no-contact outcome can now record and list its own outcomes. Previously, outcome recording and history were limited to the initial lifecycle review task, which stopped the follow-up chain at the generated task.

Eligibility is limited to customer-linked tasks with persisted outcome lineage, alongside the existing lifecycle-review task path. Existing permission checks, tenant scope, append-only outcome records, and audit events remain in force.
